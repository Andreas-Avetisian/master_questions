# Cryptographic hash functions: What is a cryptographic hash function? Which ones do you know? What are the desired properties of hash functions? What is the avalanche property?

## Cryptographic hash function

A **cryptographic hash function** maps input data of arbitrary size to a short, usually fixed-length value, the **hash value**, **digest**, or **fingerprint** of the input.

Important basic idea:

- The same input must always produce the same hash value.
- Even large input data is compressed into a small digest.
- Hashes are used where we do not need the original data, but need a compact value representing it.

Typical applications are checking data integrity, digital signatures, password verification, file fingerprints, certificates, and many security protocols.

## Examples

Important cryptographic hash functions are:

- **MD5**: produces a 128-bit digest. It is historically important but broken; collisions for the full MD5 function are known, so it must not be used for security.
- **SHA-1**: produces a 160-bit digest. It was considered strong for a long time, but is no longer secure against well-funded attackers; chosen-prefix attacks are practical.
- **SHA-2**: includes **SHA-256**, **SHA-384**, and **SHA-512**. It is still widely used and considered a good option.
- **SHA-3**: based on Keccak, standardized after the NIST competition. It is an alternative design and useful as insurance if weaknesses were found in SHA-2.
- **RIPEMD-160**: another older hash function family mentioned as an alternative in the historical context.

For an exam answer, the safe modern examples are **SHA-2** and **SHA-3**. MD5 and SHA-1 should be named only with the warning that they are no longer secure.

## Desired properties

A cryptographic hash function should have these properties:

1. **Determinism / uniqueness in repeated calculation**: hashing the same data again must yield the same result.
2. **Efficiency**: the hash can be computed quickly and without large memory requirements.
3. **Fixed-length digest**: arbitrary input is compressed into a digest of known size.
4. **Collision resistance**: it should be practically impossible to find two different messages `M` and `M'` with the same hash, `H(M) = H(M')`.
5. **Preimage resistance / not reversible**: given only a target hash value, it should be practically impossible to find input data that produces it.
6. **Second-preimage resistance**: given one concrete message, it should be practically impossible to find a different message with the same hash.
7. **Large enough hash length**: the birthday paradox means that collision search is much easier than naive guessing; therefore security-relevant hashes need sufficiently long digests.

The lecture's birthday-paradox example shows why digest size matters: finding any pair with the same hash is much easier than finding a second document for one fixed document.

## Avalanche property

The **avalanche property** means that even a very small change in the input should cause a large, unpredictable change in the output digest.

Example: changing one bit, one character, or one comma in a file should make the hash value look completely different. This is important because otherwise attackers could reason from changes in the output back to structure in the input.

## Short summary

A cryptographic hash function produces a compact fixed-length fingerprint of data. It must be deterministic, efficient, hard to reverse, hard to collide, and sensitive to tiny input changes. Modern examples are SHA-2 and SHA-3; MD5 and SHA-1 are important historically but no longer secure. The avalanche property says that a tiny input change should cause a large change in the hash digest.
